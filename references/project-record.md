# 项目记录与续接

项目内维护一份简短的 project-state.md，可复用已有项目记录。详细产物单独保存，在记录中引用。

## 长任务的续接记录

把当前状态放在已有记录的开头，每次只更新改变的几行。成果交付或暂停时记下待验状态，用户明确选择后更新决定。按需填写下列内容：

| 字段 | 续接所需的信息 |
|---|---|
| 当前任务与版本 | 本轮目标、基准版本、工作文件及部位。用项目相对路径。 |
| 已确认与待确认 | 用户明确接受的版本、范围和决定；当前新成果是否已展示、是否待答复。 |
| 本轮改动与证据 | 关联的关键参数、实际复测结果和证据路径；沿用旧证据时标明适用范围。 |
| 未决与下一步 | 已知缺陷、未实测项、具体待办；标明现在可做还是须等哪一项确认。 |

续接时先核对这几行、最新用户指示和当前工程。版本一致且证据足够即可继续本轮。缺少一项时，只查对应文件、记录条目或询问那一项；记录与工程不符时，以实际文件定位差异，重新确认受影响的决定。已生成、已检查、用户已接受分别记录。技术检查通过不会自动解锁下一任务。

## 一处维护、按编号引用

下表供按需查找详细证据字段。已有报告可直接链接，只在本轮涉及的条目中维护事实；可用 S（来源）、P（参数）、A（成果）、T（试样）加序号建立轻量索引，不强制创建数据库或独立文件。共创、制造、EDC 等条目引用这些编号，不重复抄写值和结论。参数变更保留旧版本并标记受影响成果及待重验范围。

| 记录 | 内容及用途 |

| 当前阶段与验收 | 独立任务名、成果编号及版本、实际文件、是否已展示、待验收／需修改／已接受、选项及用户结论摘要、待调整项、明确解锁的下一任务。总体授权与成果接受分开；方法默认执行不能记作用户确认 |
| 设计共识 | 主体与提取范围、还原目标及可行性结论、推荐路线与条件、待补实拍视角／尺寸及其解决的问题、生成候选待验证项；用途／场景、图片可见与假设部分、主题、必留特征、可改范围；品类候选编号、已展示项、排除理由及是否索要更多。互动动作、声音、便携、配件偏好共用一份记录 |
| 来源 S | 触发问题、原文链接／章节、访问日期与版本、作者及平台、工艺／材料／型号／单位适用范围、采用理由及缺口；库、模板及配件分别标记许可、版本／提交号。硬件数量与型号在此或配件清单维护，参数表引用来源 |
| 参数 P | 所属部位、值／范围、单位和基准、来源编号；实物硬约束／已接受设计值／待试验设计值／未知；接受版本、实测与采用状态、单边／总间隙定义、所需试样编号。变更列出保留、取消和重验项 |

## 续接与交付

按[续接记录](#长任务的续接记录)恢复当前状态和验收点。回用打印经验时核对设备、喷嘴、具体耗材、打印板、方向和相关结构条件；条件变化时重验受影响结论。资料建议、切片预测和实物观测分别标注，个人打印案例留在项目内。按问题更新对应记录，避免每次重复要求用户提供全部参数。

保存完整图纸、采用的拆分／派生图、可编辑 Blender 文件、实际执行脚本与参数、采用的参数化源与复现信息、打印几何、预览及实际切片后的工程。候选保留在项目内，不以新生成结果覆盖用户认可的基准。几何检查、切片检查、物理打印、实物配合和手感／耐久是不同证据，未知明确标记。

素材与产物路径优先相对于用户项目根目录；必要外部路径仅留个人配置。产物不写入技能安装目录，公开库不提交聊天转录、私有模型、凭据、序列号或本机路径。
