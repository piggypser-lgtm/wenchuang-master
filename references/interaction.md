# 分阶段主动共创与成果验收

## 必须执行的推进规则

以用户能独立判断的成果为单位，逐项验收。同一章节内的主视图、整套多视图、参数图等也分别交接。工具调用、截图、保存和自检属于当前成果的制作过程。

每次交接依次完成三步：

1. 自检并保存，展示实际成果、版本和关键变化。图像成果须展示可查看的图片。
2. 询问用户是否满意、有哪些调整意见，按[提问方式](#提问方式)列出选项，写明接受后开始的具体任务。
3. 等待用户明确接受当前版本，仅启动所列的下一任务。用户要求修改时，修改当前成果后重新展示、验收。

待答复期间可以保存、整理、检查当前成果或答疑，禁止在前台或后台开始下一项图像生成、建模或切片等制作。仅答复材料或尺寸、询问细节、要求调整或总体委托，均不能代替验收。用户明确要求调整流程时，按其指示执行并记录适用范围。

## 区分担忧、咨询与修改指令

用户指出担忧并提出“能否改成……”等办法，尤其明确希望助手判断时，先确认其担忧与实际部位，再检查相关截面、载荷、配合和打印方向，把所提办法作为候选而非已经批准的改形指令。说明保留或修改的依据、影响范围及可行替代；答疑不自动执行新方案。用户已经明确要求具体修改且范围清楚时直接处理，不借此反复索要确认；需要设计取舍时沿用当前成果的选项确认。

## 提问方式

每轮询问 1–3 个与当前任务有关的问题。方案讨论有合理候选时给出 2–3 个，说明外形、功能、难度或制造取舍。“给我提供更多选项”等另计。

验收时写明成果名称和版本，提供以下选项，也接受自由补充：

- **满意，进入【具体下一任务】**。用户回复编号或明确表示“这版可以，做参数图”等即可推进，无需再次点击。
- **不满意／需要调整，修改当前成果**。已说明改动就直接修改，未说明则给出针对性的调整方向并询问。修改后重新验收。
- **先解释或放大查看，暂不进入下一步**（按需提供）。说明、放大或对照后，再次提供验收选项。

“继续”同时附有修改要求时先修改再验收。回复含糊或相互矛盾时先澄清。沿用已知事实和同版本、同范围的明确验收结论。

优先用宿主当前允许用于确认的选项工具。工具不适用时直接在聊天中列出编号，不切换模式或限定特定工具。沉默、超时、默认预选、工具成功或异步返回、空答复和本轮结束均不能替用户作答，保持“待用户验收”。

## 品类建议的固定扩展选项

按[标准共创](co-design.md)展示品类候选，每轮都单列“给我提供更多选项”。同时提供接受具体候选并讨论用途、调整偏好并修改当前建议的选择，允许自由补充。工具放不下所有选项时，在聊天中完整列举并编号。

用户选“更多”时，保持本轮待验收，按已有约束补充不同候选并记录已展示编号。用户已指定产品时，提供该产品的内部变体。

## 建模分工、环境与生成确认

用途阶段初判 [协同建模](hybrid-modeling.md) 分工，完整多视图接受后确认必要拆分；参数图接受后按 [建模计划](modeling-plan.md) 确定执行工具、当前独立成果及试样返回节点；按 [环境配置](setup.md) 核验所选组件。路线选择、安装、账户连接、上传／付费生成计划和候选接受分别记录，不互相代替。已有可用环境不重复安装，同一范围已有明确授权时沿用。

Tripo／Flexi 主体或局部外观候选及独立结构方案须单独验收；普通已确认草模内的参数化零件按事前范围随草模验收。具体判定和试样子流程以建模计划为准，不把新增分支当作省略阶段确认的理由。

## 细化方法的事前告知与默认选择

用户已明确提出细化目标，但未指定调整方式时，在执行前说明拟用方法（如局部雕刻、顶点调整、布尔、重拓扑或减面）、修改范围、选择理由、可能影响及回退方式。提供“按建议方法处理”“改用其他方法”“暂不执行，先解释”等选项；已有具体方法指示时沿用，不反复征询。

对于已授权任务范围内、不改变已确认设计或接口要求、可在副本上撤销的技术方法，这是可选的方法偏好征询。说明默认方案及答复窗口，例如“计划先在副本上做局部雕刻；如想换方法请告诉我，若约一分钟内没有新的意见，我会按上述默认方法试修”。简单选择留出至少约 60 秒，复杂方法比较留更长时间；期间只做当前任务内不依赖该选择的读取、备份和检查，不先执行待选择的方法。若用户要求停止、换方法或进一步解释，按其新指示处理。

窗口结束而没有答复时，只能依据已有任务授权执行已告知的默认可逆方法，记录“未回复，按已授权范围内的默认方法执行”，不能记录为用户确认。此机制不适用于阶段成果验收、尚未明确的造型/接口取舍、不可逆变更、安装或发送打印等需要明确批准的事项；这些问题保持待答复，时间流逝不构成批准。用户要求每次方法也必须确认时，遵从该要求。

工具空返回或预选不等于答复窗口已经结束；宿主无法持续等待或会话已结束时，不承诺后台自动执行，不自行创建定时任务。续接时先检查新增回复、当前版本及授权范围。方法改变或超出已告知范围时重新说明；最终成果仍须按选项式验收后才能进入下一任务。

## 典型交接

| 当前成果 | 展示和提问重点 | 验收后的下一步 |
|---|---|---|
| 主体与提取范围 | 选对对象了吗，整体/局部是否符合意图 | 可行性判断 |
| 可行性结论 | 是否接受还原目标、推荐路线及其条件；结构看不清时是否先补对应实拍，或调整当前范围 | 可进入设计且获接受后进入品类探索，已指定品类则沿用；需补信息则留在当前结论补核 |
| 品类探索 | 接受候选进入方案讨论、调整偏好，或给我提供更多选项 | 用途方案；索要更多则留在当前任务 |
| 用途方案 | 功能和保留特征是否满意 | 参数建议与查证 |
| 参数建议 | 尺寸、接口及采用依据是否合适 | 主视图 |
| 主视图 | 主体、视角、比例与轮廓是否满意 | 以该主视图为基准生成其他视图 |
| 其他视图与整套多视图 | 是否与已确认主视图一致，方向完整、补充结构是否接受 | 判断部位拆分；需要取舍则确认方案，否则制作完整参数图 |
| 部位拆分方案（需要时） | 保留／省略／代码重建区域、连接及过渡，是否影响最终造型 | 受影响造型先修订验收，再制作完整参数图 |
| 带参数产品参考图 | 主展示／正／左／右／顶视图及必要详图、标注、结构和功能关系有无调整 | 建模路线选择与环境检查 |
| 建模分工 | 外形与功能机构分别由哪些工具完成，候选／试样交付范围 | 所选环境核验、必要安装方案 |
| 环境核验结果 | 所选组件安装／启用／认证／连通状态，是否需修复 | 按约定进入直接代码草模、生成输入准备或试样方案 |
| 派生主视图（需要时） | 是否只去除指定部位，剩余主体及闭合假设是否接受 | 按多视图规则补齐其他必要视图并整理本轮整套输入，不直接生成模型 |
| 其他派生视图与本轮整套输入 | 新图及复用图是否与派生主视图、完整设计和拆分清单一致，必要方向及上传子集是否明确 | 外部生成计划确认；主视图已接受不代表本项自动通过 |
| 外部生成计划（按所选工具） | 输入版本、上传范围、步骤、次数与预算 | 在授权范围内生成候选 |
| 独立候选（Tripo／Flexi／结构模块等） | Blender 实际几何、图纸对照及接受范围；Tripo 必须提供适用的保留再生成、修改输入重生成及代码修复选择；阻塞问题不放行 | 明确接受保留区及替换方案后进入对应功能草模／整合；重新生成及后期替换按 Tripo 分支返回受影响节点，不自动接受整件 |
| 草模 | 与确认图是否一致，体量、机构极限状态与功能是否满意；高风险项及细化依赖 | 优先进入所需原尺寸试样；验证充分或明确延期范围后，仅进入已解锁的细化 |
| 试样方案 | 目标、原尺寸及根部、实际层向、安装与施力条件、极限状态、试验参数及返回节点 | 样件建模 |
| 样件模型 | 真实接口、验证范围及几何检查 | 样件导出检查，再逐项走打印子流程 |
| 试样反馈与参数结论 | 实测结果、采用值、延期或失败处理 | 返回约定的草模、细化或拆件节点；变更先修订受影响设计 |
| 细化模型整体验收 | 整体造型、细节、配色及功能是否满意 | 准备按已确认色区拆件的方案或沿用结论 |
| 按已确认色区拆件方案 | 拆哪些部位、接缝在哪里、怎样连接和装回；是否调整或保持一体 | 只制作接受的拆件；确认无需新增拆件则进入导出检查 |
| 拆件与装配结果（实际拆件时） | 分解与复装视图、各件实体、接口、外观和功能是否接受 | 满意后进入导出检查；需调整则留在当前成果 |
| 导出检查结果 | 实际导出尺寸、零件和实体检查结论是否接受 | 打印方案 |
| 打印方案 | 本轮选定／排除件、数量及材料映射；按各件精细度和结构决定朝向、参数、支撑与分盘的取舍 | 摆盘和参数配置 |
| 摆盘和参数配置 | 优先代码准备、作为工程打开核实实际生效；沿用用户已完成操作，展示逐件／逐盘材料、参数差异、支撑和数量 | 明确接受后单独调用程序化或界面切片，不与工程准备连跑 |
| 执行切片、逐盘交付与预览 | 按 [每盘切片文件交付](bambu.md#每盘切片文件交付) 逐盘先列本轮共用的可编辑工程及盘号，再列该盘 G-code，展示本轮逐层路径、预计用时、耗材与警告处理；询问是否接受本轮切片结果 | 接受后核对本次打印授权；需要调整则返回受影响节点，确认后重切相关盘 |

## 状态与续接

项目记录保存当前任务、成果版本、展示状态、验收状态（待验收/需修改/已接受）、用户实际选择或等价文字的结论摘要、待调整内容及明确允许的下一任务。只保存结论，不保存逐字聊天。续接时先核对该状态；没有记录的验收不能凭猜测补全。总体任务授权和具体成果验收分别记录。
