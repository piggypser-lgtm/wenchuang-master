# 外观生成与代码结构的协同建模

本文件维护路线判断、部位职责和严格功能区域的处理。图纸制作与派生视图以 [多视图设计](multiview-design.md) 为准；工具交接与试样以 [建模计划](modeling-plan.md) 为准；实际执行及检查见 [Blender](blender.md)。默认推荐 Tripo 外观＋Blender 代码功能结构，但先判断直接代码建模是否更简单可靠。部件级 CAD 工具按下表选择。所有路线最终在 Blender 中检查、修改和展示实际模型。

Sand3D 仅可作为 Blender 代码路线内的 [可选几何函数封装](sand3d.md)，复用已验证的操作，不增加数据集检索、外观生成或独立建模路线；代码来源不改变精度、可打印性及统一验收责任。

## 1. 在用途设计中判断路线

按 [可行性判断](feasibility.md) 先区分忠实复原与允许创作的范围，分别评估外观获得、功能精度、整合修整和可打印性；照片无法判断关键结构时定向补实拍。可行性阶段初判，用途方案中结合产品目标明确部位分工；正式工具／环境确认仍在参数图验收后，不提前创建几何。复杂外观可走生成路线，实际候选的可修整性仍须验证；新问题在当前节点更新相关结论，不新增一套验收。

| 当前对象与要求 | 推荐处理 |
|---|---|
| 基础几何、可描述的轮廓／规则曲面、简单卡通形体，尺寸和修改能受控 | Blender 代码直接建模；跳过 Tripo 安装、生成与候选步骤，保留图纸和草模验收 |
| 有机、角色或装饰外形复杂，功能结构可独立定义 | 默认 Tripo 外观生成＋Blender 代码建立精确功能结构与整合 |
| 某外观部位同时承担精密承托、夹持、安装或活动功能 | 按功能精度分区，比较保留后调整、重建接触面／内核、独立代码重建整个部位 |
| 精密功能部件需要 CAD 实体或频繁按尺寸重建，Blender 现有方式成本较高 | 说明收益后可选 CadQuery 生成该部件，再回 Blender 整合验收；不改变其他部位的既定路线 |
| 曲面需按多个截面同时控制宽度、厚度或圆角，并保持与功能面的过渡 | 可选 [SMLib 多截面放样](modeling-tools.md#smlib-多截面曲面)，只对需要这种控制的部件使用 |
| 已有合适且可使用的模型／CAD | 导入 Blender 接收检查，再补结构；不强制再次生成 |
| 参数化模板或专项分节工具更适合 | 说明收益后按已确认路线使用，统一回到 Blender 验收 |

判断结合还原难度、参数可控性、修改成本及当前工具能力，不以“理论上能写代码”判为简单，也不因强调混合建模而强制消费 Tripo 积分。用户已有明确路线可沿用；不可行时说明原因与替代，不能擅换目标。Tripo 未安装、不可用或用户暂不生成时，只有直接代码路线经评估适用才提供该替代，不能无条件兜底。

结构方案来源与执行工具分开选择：先按 [成熟机构复用](mechanism-reuse.md) 评估有许可、证据及适用条件的方案，再按现有环境、参数修改与复现便利性选择执行工具。自行建立常规功能结构优先复用 Blender 代码能力；采用成熟参数源时保留其原生实现，不为统一工具重写已验证核心。外部工具和函数库各按实际收益选用，不为套用资源增加平台切换或安装。

用途方案同时确定外观必留特征、功能区域、连接基准、配合物和运动／取放／装配空间。严格功能参数从绘图前就约束设计，不等到生成后才补。机械结构包括静态承托、孔槽、内腔和连接，并非只有可动机构。

## 2. 整体多视图后的部位拆分判断

完整造型多视图先展示并验收，然后按已确认用途检查功能区与外观区是否耦合。没有收益时直接进入完整参数图；需要实质取舍时展示标注部位的二维方案并等待明确选择：

- 保留完整造型生成，后续在 Blender 局部调整。
- 去除指定部位，生成主体后用代码重建；或单独由 Tripo 生成该部位的外观，再由代码建立精确接口。
- 保留装饰外轮廓，只用代码建立精确接触面或内部功能结构。
- 当前形体足够简单，改为直接代码建模。

说明具体部位、边界、保留／去除／重建内容、连接位置、剩余主体如何闭合，以及外观与制造代价。不因部位名称而自动删除，也不把方案选择当作图纸或生成授权。已明确接受过同一拆分范围时直接引用。方案影响完整设计时先更新受影响造型图并验收，再制作完整参数图。

建模部件独立不等于必须分件打印。最终合并为固定整体还是保留装配件，按设计及 [连接原则](design-rules.md) 确定。派生生成图仅临时省略待重建部位；完整产品设计始终是最终目标。拆分方案接受后，在完整参数图中落实接触关系、接口、方向、连接范围和过渡空间；派生图制作放在 Tripo 输入准备阶段，遵守 [派生图顺序](multiview-design.md)。

## 按部件生成外观

设计阶段可将主体和局部外观拆为独立生成任务，逐部位记录“外观由谁生成、精确接口由谁建立、装回哪里”。无需每次重新生成整个产品；已接受的主体和无关部件保留。分部件生成不是把精密关节交给生成器：其外形可由 Tripo 提供，连接轴、孔、肩座等仍按参数精确建立；默认用 Blender 代码，已选择 CadQuery 的部件可先生成后接收，最终均在 Blender 验证。

局部输入图按 [多视图规则](multiview-design.md) 先主视图确认，再补必要方向；采用容易辨认、与已确认最终设计兼容的姿态，明确左右、内外或掌心／手背、连接端及装回时的坐标关系。标记放在说明图，实际上传图保持干净。改变刚体摆放可说明变换；若需要改变手势、弯曲或局部造型，先修订受影响设计，不把形变当成简单旋转。

每个局部候选在 Blender 独立接收检查和验收，可放到装配预览副本中核对比例、朝向及连接空间，未接受前不改主体或建立接口。接受后再按已确认参数完成接口与整合，复查整机外观、过渡、装配与运动干涉；局部外观接受不等于整机已接受。后期新增局部生成，只返回受影响的分工、局部图及生成计划节点，沿用未变部分的确认。任务、候选、次数和费用逐部件按 [Tripo 流程](tripo.md) 记录。

## 候选的接受范围

候选验收针对当前外观基础，展示以下区域及其状态，不要求提前完成尚未授权的功能建模：

- **保留区：** 对照已接受完整／派生图检查，达到当前外观候选的要求；已有非预期凸起、破面、异常过渡等按 [模型交付检查](blender.md) 处理，不能留给用户自行发现。
- **计划替换区：** 明确边界、为何删除／替换、由谁补回、连接和保护范围及合理可行的重建方案。用户接受该范围后，不为随后必然丢弃的几何反复精修；功能区可在下一功能草模中重建。外观部位的局部修复／重建仍按 [Tripo 候选流程](tripo.md) 留在当前任务验收。替换区的问题若影响保留区、连接根部或可整合性，不得借范围划分放行。
- **阻塞问题：** 保留区存在未处理缺陷、边界或关键尺寸无法确定、缺陷影响范围未明、替换方案无可靠依据等，先留在当前任务修复、补信息或调整方案；不能把“以后再修”写成通过。

接受时记录“保留外观已接受／替换区及补回方案已接受／功能待建立”等实际状态，不能宣称整个候选无缺陷或整件可打印。接受范围须由用户明确确认，不能靠技术方法的默认等待规则改变。后续草模按清单恢复全部应有部位，最终细化和导出检查实际交付几何，不继承候选的临时替换区豁免。

## 3. 功能参数与外观之间的交接

每个严格功能区记录：用途、几何／角度基准、目标值及来源／试验状态、允许偏差或待定状态、连接范围、保护区和验证方法。不能以“部位看起来倾斜”替代可测的承托关系；曲面要明确接触点、接触面或局部切线等实际定义。

承托类产品先明确配合物真实尺寸、使用姿态、支撑接触、挡边及必要净空；样板保持真实尺度。按参数用代码建立功能几何，再使装饰形体适配已认可的功能范围。严禁反过来把硬尺寸改成生成网格的近似尺寸，或整体缩放配合物以掩盖不适配。

生成网格不是自动带有可编辑功能参数的 CAD。是否能精确修改取决于部位可分离性、拓扑、厚度及目标形变。候选接收时可测量和展示空间偏差，不在候选未接受时开始功能建模；只接受外观基础也须说明预定的结构修复／重建范围。保留的几何需对照完整设计；有意省略区域对照已接受的派生图及拆分清单，不能误报为生成缺陷或最终完成。

## 4. 严格功能区的调整与重建

功能草模阶段按偏差选择方法，细化不能代替草模解决已知硬参数缺口：

| 情况 | 方法与检查 |
|---|---|
| 外形基本适合，仅位置／方向偏差，局部可以隔离 | 在副本局部变换或受控变形；测量实际接触关系，检查过渡、厚度与保护区 |
| 外轮廓适合，承托面、挡边、孔槽或连接不精确 | 保留装饰区域，用参数化代码切除／重建功能接触面或内核；复核厚度与路径 |
| 大幅弯曲、截面或网格质量使局部修改不可控 | 建议隔离／移除原区域，按参数和设计轮廓重建部件，再连接并检查整体 |
| 当前资料或能力无法可靠完成 | 明确未验证和限制，提出补资料、简化或换路线，不承诺任意网格均能修准 |

主动提出代码重建的时机：用途／拆分设计发现硬参数耦合；候选接收发现偏差；局部试修无改善或产生新缺陷。不要等反复失败才提供该选项，也不为了局部孔槽问题无限重新生成整个主体。改变既定部位分工、输入图或外观时明确确认并修订相关图纸；当前已授权范围内的可逆技术方法仍按 [交互规则](interaction.md) 告知，不把方法默认窗口用于部位删改决策。

## 视觉特征的制造交接

沿用 [产品方案](products.md) 已选的制造方式，在候选接收时以设计图和中性材质预览核对必留视觉特征；输出带纹理时再作对照，区分眼睛、嘴部、标志、花纹等是实体几何、仅贴图，还是尚未生成。只记录影响辨识和制造的特征，引用现有部位编号，不另建重复清单。

| 已选实现方式 | 交给哪个现有步骤落实与核验 |
|---|---|
| 浮雕、凹刻或其他真实凹凸 | Blender 在已授权草模／细化范围建立实际几何；核对细节尺寸、厚度及导出后是否保留 |
| 同一实体的多材料颜色分区 | 建模／导出保留可识别的分区依据；切片配置阶段用已验证的材料分配或涂色方式实现，并在实际切片检查，贴图不自动当成色区 |
| 独立嵌件、分件装配 | 原有功能分件按建模计划建立。整体验收后，按 [已确认色区拆件](blender.md#按已确认色区拆件) 复用合格部件、落实获选的新增色件与装配 |
| 已明确选择的后处理 | 交付说明待完成的上色等操作与目标区域，不宣称打印已经呈现最终颜色或细节 |

现有方案明确时沿用，不重复询问；原方案未选、生成结果暴露实现缺口或需要增加零件／改变外观时，在当前候选成果中展示选项并明确确认，必要时返回受影响设计。不得为了补贴图擅自增加浮雕、分件或后处理。候选接受只确认特征实现分工。各特征在对应的草模、细化、按色拆件、导出或切片阶段核验实际实现，已有配色直接沿用。

## 5. 代码资产与统一验收

默认通过 Blender MCP 实际执行建模代码；已为该部件选择外部 CAD 时，按 [工具执行与接收](modeling-tools.md) 运行相应脚本并将实际生成的网格导入 Blender，不能以离线脚本文件代替已执行的几何。将关键尺寸集中为带单位、基准和含义的参数，保存实际执行的脚本、输入模型版本、必要依赖和运行顺序。外观源模型、结构源对象、整合派生对象分别保留。脚本只操作项目指定集合／对象，重复运行前检查已有结果，提供定向替换或重建方式，不能重复堆叠或覆盖人工细化成果。

改孔径、安装件或间隙时优先重建对应结构；布尔、平滑、重拓扑和减面后重验接口，不能把全局处理造成的尺寸偏移当作外观优化。保存脚本不等于已验证可复现；需要宣称可重建时，在隔离副本实际执行并检查，只报告验证过的范围。人工修形保存模型检查点及操作说明，不声称脚本能还原未记录操作。

代码模型、Tripo 候选和其他来源都在 Blender 中用实际几何展示、检查并按范围修改。网页效果、设计图或运行成功不代替验收。每次交付分别报告外观、功能结构、结合处三个检查维度，可合并在同一次成果展示中，不另增三次审批：

- 外观：按完整设计核对比例、轮廓、特征；主体候选的省略区域按已确认拆分／派生图解释。
- 功能：按参数测量尺寸、角度、厚度、间隙及路径；尚未构建的候选功能标为待完成，不能算通过。
- 结合处：检查布尔接缝、穿插、异常凹凸、过渡、局部薄壁及连接；整合后确认所有应恢复部位已恢复。

外观还原优先级不授权牺牲硬参数，功能要求也不授权暗改外观。冲突时先展示取舍、修订相关二维依据并验收。最终细化和导出对照完整产品图、实际参数及所有应交付零件；派生无部件主体永远不能替代整件验收。
