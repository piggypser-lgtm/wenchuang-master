# 主体与混合建模可行性

在主体结论获接受后、正式设计图与几何创建前给出初判。判断的是当前目标能否通过合适路线获得、修改、整合并制造，不能把“难以直接写 Blender 代码还原”当成不可行，也不能把“Tripo 能生成外观”当成可打印产品已成立。共同路线见 [协同建模](hybrid-modeling.md)。

## 先明确还原目标与资料边界

沿用已确认的主体范围、必留特征和用户要求，只补影响判断的信息：

- **图片特征转化为文创设计：** 可以讨论风格化、姿态调整或不可见面的原创补全；由用户接受具体假设，后续以已确认设计图为外观验收依据。生成多视图能表达设计选择，不能证明原实物背面、内部或尺寸真实如此。
- **忠实复原特定实物：** 关键形体、身份特征、连接及尺寸需要对应证据；不能用生成器猜出的背面、贴图相似或视觉上合理的孔槽冒充精确复原。要求越严格，越应补真实照片、尺寸或已有设计源。
- **用途尚未选择：** 先判断主体可转化的范围及明显限制，功能、尺寸与制造细节标为后续共创／参数任务待定。不能因用户还未选品类或尚未填写所有参数就拒绝主体，也不能提前承诺所有产品方向都可做。

### 照片看不清结构时，定向补拍

照片不足以判断主体连接、前后层次、关键空隙或功能结构时，先指出具体不确定处，优先请用户补充同一实物的更多视角照片，并说明每张照片要解决什么问题。例如：侧面看弯曲与前后距离，背面看连接方式，底部看支撑／开口，连接处近照看部件边界；结构在不同状态下变化时，可请补充正常打开／闭合状态。不笼统要求“再拍几张”，也不对所有对象机械要求完整一套照片。

补拍尽量保持主体、姿态和装配状态一致，变化需说明；关键遮挡应在新增视角中露出。精密尺寸另用实测或规格确认，不从透视照片直接推定公差。只有图片不能回答的内部结构，可请求已有剖视、CAD 或可正常查看的内部照片，不要求用户破坏性拆开物件。

无法补拍时，说明哪些结构仍未知，提供接受限定的原创补全、局部提取、平背／浮雕或暂缓该目标等实际合适的选项。用户未选择前不默认为可猜测；要求忠实复原且关键结构无证据时，保留缺口或拒绝当前精确目标。AI 生成的侧／背视图不能替代实拍补证，补拍本身也不等于设计图已完成或获接受。

## 分别评估外观、功能、整合与制造

| 判断面向 | 可行条件与需要识别的缺口 |
|---|---|
| 外观获得 | 简单轮廓、规则曲面可直接代码建模；有机角色、褶皱或装饰曲面可评估 Tripo 外观生成。检查主体清晰度、遮挡、姿态和必留特征，区分真正需要成形的几何与仅在颜色／贴图中的细节。复杂程度只影响路线与修整代价，不是类别禁令 |
| 功能精度 | 用途、配合物、接触／安装基准和空间能否明确；优先采用有适用证据的机构，或由 Blender 代码建立功能区，确有收益时按既有规则选择 CAD 支线。生成孔槽、角度和内部结构不当作硬参数依据；当前缺失会改变可行性的重要实物信息先补齐 |
| 可修改与整合 | 能否保留必留外轮廓，隔离功能区域，重建接触面／内核或整个部位，并留出壁厚、根部及过渡空间。提出有依据的修整路线，不承诺任意生成网格都可修准；若修复需要重做大部分关键外观，重新比较分部件生成、代码重建、既有资产或调整方案 |
| 可打印与使用 | 在目标尺度与材料下，关键细节、薄段、空隙、装配／运动空间、打印方向和支撑拆除是否有可行处理。毛发、羽毛、细枝、透明／反光或复杂镂空分别检查信息缺失与制造问题，不按类别一律拒绝；需加粗、合并或删减必留特征时先让用户选择 |

图片还不足以确定的拓扑、实际厚度、融合缺陷与修整难度，记录为生成候选接收时的检查项；不能假装已测过。高面数不是自动拒绝理由，按后续保形优化规则处理。渲染、纹理、分割结果或 STL 导出成功均不替代实际几何和功能验证。

## 推荐路线与环境状态分开写

根据上述判断，按 [协同建模](hybrid-modeling.md) 推荐直接代码、Tripo 外观＋代码功能、分部件混合，或沿用合适的已有模型／参数化源。对兼具外观和承力的部位，初判可保留外轮廓并重建功能面，还是需要整个部位代码重建；只是路线建议，正式拆分仍在整体多视图验收后决定，不提前删改或生成部位。

把“设计路线有依据”与“当前工具可执行”分别记录。Tripo 未安装、未连接、余额不足或某入口不支持所需输入，是环境／执行条件，不自动意味着主体不可建模；也不能隐藏这些条件。存在可补齐的接入或人工生成后导入路线时列为待办；若当前约束排除了所有可执行路线，明确当前不能执行。早期只读发现能力，不上传图片、不安装、不付费生成、不试建模；正式环境核验与生成计划仍按 [建模计划](modeling-plan.md) 和 [Tripo 流程](tripo.md) 的原有节点进行。

工具能力以实际入口和当前官方文档为准；[单图接口](https://developers.tripo3d.ai/en/docs/generation-image-to-model/standard)与[多视图接口](https://developers.tripo3d.ai/en/docs/generation-multiview-to-model/standard)的输入能力分别核对，不把某一入口的功能推广给所有插件，也不在可行性文档硬编码版本、积分或成功率。

## 保留三种明确结论

1. **可进入设计（注明直接／混合／附条件）：** 当前资料支持所选还原目标，存在合理的功能和整合路线。允许复杂外观走生成路线，候选能否达到要求留待实际接收验证。若需要接受隐藏面原创补全、限定还原范围或额外修整代价，在当前结论中说明并等待用户选择；接受后才进入下一阶段。不能要求先成功生成模型才能开始设计，也不能把待验证项写成已通过。
2. **先补信息或调整方案：** 缺口会改变当前判断，例如关键连接被遮挡、配合物身份不明、功能区没有容纳空间，或必留细节与制造尺度冲突。明确应补哪个视角／尺寸，或比较分部件路线、已有源、局部提取、尺度／造型调整；由用户选择。只阻断依赖该缺口的任务，不因后续参数阶段才能确定的普通设计值而把整个主体判为不可行。
3. **拒绝当前目标：** 在现有资料、允许改动、工具与制造约束下，没有能够可靠建立和验证的路线；例如坚持仅凭被遮挡单图精确复原内部机构，或坚持目标尺度无法制造的细节且不接受调整。指出无法满足的具体要求和原因，提供可行的替代范围，不将“复杂角色”或“代码不好写”作为拒绝理由，也不靠无限生成掩盖不满足。

用一张简短结论卡展示：**还原目标及依据 → 推荐路线与部位初判 → 关键假设／待验证项 → 环境待办与补充资料 → 当前结论及具体下一任务**。内容引用同一份 [项目记录](project-record.md)，不重复制作评分表。依 [交互规则](interaction.md) 提供满意并进入具体下一任务、调整当前结论、必要时先补照片／解释等选项；未接受不继续。附条件进入设计不等于接受生成候选、授权上传付费或保证打印成功。

## 在现有节点用新证据复核

用途与参数收敛、整体多视图后的拆分判断、Blender 接收实际候选以及出现新的修整／制造问题时，只复核受影响的可行性结论，纳入当前成果展示；不额外新增审批阶段或把无关已接受成果全部重做。

实际候选暴露粘连、缺件、关键负空间丢失或功能区域无法隔离时，按 [Tripo 接收](tripo.md) 比较保留候选再生成、修改输入、局部修复或代码重建。改变既定造型、拆分或输入的选择先确认并回到受影响图纸；功能草模前不把候选外观接受当作功能已完成。预算／次数用尽或没有新的改善依据时停止重复提交，不能把换用全代码当成必然可行的兜底。

例如：造型复杂但结构清楚的吉祥物可评估混合路线，不必自动降为浮雕；弯曲装饰部位兼作手机承托时，可提出保留外观、代码重建接触面或整个部位；只有正面照片且看不清背面连接时，优先请补背面与连接处近照，无法补证又坚持精确复原时拒绝该要求。这些是判断示例，不是特定模型的成功保证。
