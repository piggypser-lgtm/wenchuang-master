# 标准共创：从品类探索到图上调整

默认采用标准共创：先通过品类库探索用途，再比较有实质差异的概念，绘图时围绕具体设计点逐轮调整。用户可要求深度探索或直接细化已有想法；沿用已确认信息，不强制重复头脑风暴。各独立成果仍按 [分阶段交互](interaction.md) 验收，沉默不能推进阶段。

## 画图前的设计意图

主体与可行性获确认后，在品类探索任务内分轮了解尚未知的使用对象、场景、想解决的问题、图片中必留特征、允许的简化或夸张，以及不喜欢的样式。每轮聚焦 1–3 个相关问题，提供具体选项并允许自由补充，不让用户一次填完整问卷。

邀请用户说明个人记忆、地方特色或主题含义，但这些不是必填项；普通个人图片同样适用。区分用户提供的故事、可查证的文化信息与 AI 提出的创意联想，不把联想写成历史事实。

## 品类探索与继续扩展

用户未指定产品时，读取 [可打印文创品类库](product-library.md)，遍历大类并筛选与图片和当前用途有关的原型。展示简短探索地图：适合、需改造或补信息、暂不推荐，并说明主要理由；不要把初步适合写成已验证可打印。

可按 [品类库的 MakerWorld 入口](product-library.md#makerworld-的按需查阅) 补足真实案例；基础讨论不强制联网，用户问最新热度时须实时查证。关节动物、动态景观、灯光文创及组合解压按库中的基础／进阶原则说明制作负担，沿用既有预算和配件偏好。

默认给出三个尽量跨品类、用途有明显差异的推荐，说明各自如何保留图片特征、如何使用和主要取舍。每次提出或更新品类建议，都必须在候选之外另列一个完整、可选择的 **“给我提供更多选项”**，不能仅写“也可以继续问我”。该选项不占推荐产品名额；候选与控制选项可超过通常的 2–3 项。

选择“给我提供更多选项”后：

- 留在当前品类探索任务，保留既有偏好、排除项及备选，默认再给三个尚未展示且合适的原型，优先补充未覆盖的大类。

- 新选项应有不同用途、结构或使用场景；仅换颜色、名称或主题不算新品类。不暗中放宽预算、材料、尺度、已认可的用途或建模能力要求。

- 每轮继续提供“给我提供更多选项”，并可提供“展开某一类”“查看当前库内全部筛选结果”；不强迫用户必须从本轮选一个。

- 可行候选不足时如实说明，不凑数、不循环推荐已否决项。用户继续索要更多时，可说明需要补充偏好、按需联网拓展，或提出需要用户同意的约束调整；没有同意前不采用新约束。

- 用户要求穷举时，按大类列出当前库内的适合、待确认和排除结果及理由；称为“当前库范围内的系统遍历”，不声称覆盖所有可能的文创产品。

候选使用稳定编号，便于用户回选前几轮方案。选择候选并明确愿意深入，可作为当前品类方向的接受，只解锁用途方案讨论；索要更多、询问理由、仅表达偏好都不等于验收。用户已经指定产品或明确接受过该品类时，直接沿用，不重新要求选择；在该产品内部提供设计变体，也保留“给我提供更多选项”，默认不扩展到其他产品。

## 桌面数码场景的按需扩展

用户提到桌搭、耳机／手柄架、小设备收纳或充电支架时，读取 [桌面数码配件与收纳](desktop-digital-accessories.md)。沿用已知设备与偏好，分轮补充设备组合、使用位置及现成充电器／线材需求；按当前阶段提供用途不同的候选或同品类变体，继续保留“给我提供更多选项”。商品目录帮助扩展用途，参数化库帮助比较结构；选定用途后才在参数任务中查具体型号与尺寸。

默认只设计成品设备及充电组件的外围承托、固定和理线。固定充电器不自动触发电路、供电控制或 CyberBrick 分支；需要新增电子功能时仍走下方统一入口。模块化只有换位、扩展或维护收益明确时才作为候选，沿用最少零件原则，不增加一套确认阶段。

## 用途方案与设计共识

品类方向接受后，围绕所选产品默认提出三个实质不同的文字概念，可分别偏向形象保留、功能融合、创意转化。差异必须体现轮廓、功能结构、使用动作或主题表达，不强行套用三种标签，也不为凑数量推翻用户明确想法。

每张简短概念卡说明：图片特征、具体用途、造型转化方式、保留与改变的部分、主要取舍、未验证条件。可用轮廓保留、局部放大、负空间利用、浮雕/剪影、姿态重组、可替换局部等方法组合；参考库是启发，不是只能从中选模板。

按 [协同建模](hybrid-modeling.md) 在方案中初判外观与功能区域的职责、精度、连接与预留空间；简单形体优先直接代码建模。兼具装饰与功能的部位不能只按外观分给生成器；具体拆分在整套造型图接受后确认。此时只讨论，不创建三维几何。

允许选择单一方案或组合不同方案的局部。组合前检查功能、轮廓和接口是否冲突，不能直接拼接。将收敛后的方案写成简短设计共识卡：用途与场景、主题、必留特征、允许调整、禁止改变、待定问题。展示并获明确接受后，再进入参数查证与建议；品类选中不等于概念方案已接受。

文字不足以比较时，先让用户选择是否加入二维概念草图探索。草图只能是同一拟定主视角的概念候选或局部二维示意，标记“探索稿、非尺寸依据”；先展示并接受这一独立成果，再进入下一任务。不得借草图探索提前生成未验收主视图的其他完整视图，不得先建立三维草模。关键参数仍须在正式主视图前查证并验收，概念草图的接受不能替代正式主视图验收。

## 用途方案中的互动与机构共创

这是功能活动、解压把玩与电子扩展的统一提问入口。在品类接受后、用途方案验收前，主体特征或用途适合活动时提出一次具体建议；品类探索中的 K 类只介绍产品方向，选定后在此细谈。已有活动／解压选择直接沿用，不另开重复问卷。

提问示例：“【部位】可以设计成【动作】，带来【用途或互动】，同时会增加【主要取舍】。你希望保持固定、加入局部活动，还是先比较两种方案？”候选之外保留“给我提供更多选项”。已明确要解压玩具时，直接提供具体机构候选，不再询问是否要解压；不强迫改变已有品类。独立把玩可以作为用途，保留用户原有功能与预算约束。

### 从主体特征推荐互动玩法

先沿用已确认的主体结论，将可见特征转化为玩法候选：**特征／部位 → 用户动作 → 可感知效果 → 机构卡及证据 → 主要代价**。以下是创意匹配线索，不是仅凭图片就能确认的机械可行性：

| 主体特征 | 可优先讨论的互动 | 匹配时需确认 |
|---|---|---|
| 圆形、花瓣、蘑菇帽、上下两层轮廓 | 旋转段落、齿轮联动或转盘；可查 M06／M07 | 握持与旋转空间、需要的磁铁、夹缝及稳定性 |
| 头顶、角、耳朵、按钮状突出或可切换表情 | 按压回弹（现成机械轴安装可查 M13）、同向两态按压，或左右翻转切换 | 三种动作分别说明；M13 需外购轴体，不是纯打印回弹或按压锁止 |
| 方块、可分块纹样、连环画面或多种表情 | 连续翻折与图案重组；可查 M12 | 铰链朝向、块间碰撞、实际件数及牺牲薄条清理；不按单次打印计件 |
| 翅膀、手臂、尾巴、可分离的装饰部位 | 手摇摆动、点头、挥手或扑翼；可查 M08 连杆 | 动作范围、外观件质量／力臂、连接位置与根部 |
| 鳞片、条纹、长条背部或可分节躯体 | 卷带滑动、串联弯曲；J06 关节动物可查 M05 | 空间、摩擦与卡滞、链节数、柔性材料或打印方向；不把自由弯曲当成承重定姿 |
| 建筑、山水、车轮、水车或重复景物 | J07 局部手摇景观、J08 滚珠路径；联动可查 M08 | 输入动作、运动空间、回收方式；循环提升与多机构同步单列为进阶玩法 |
| 肉垫、肚子、泡泡状圆顶 | 软弹按压、回弹触感 | 是否接受 TPU 等额外材料和嵌件／装配工序，不能默认 PLA 有同等弹性 |
| 可分成盖体与盒体的轮廓、主题容器 | 旋转搭扣开合；可查 M09 | 操作可达、闭合位置、安装方式及实际总件数 |
| 细长颈部、花茎、触角或适合轻摆的局部 | 弹性摆动与回弹；可查 M10 | 新增重量／力臂、变形空间、材料与层向，不能直接推定耐久 |
| 层叠花瓣、塔形、波纹或适合伸长／收回的角色局部 | 轻质拉伸／收合、错层展开；轴向滑移兼翻转可查 M14，套层容器升降／转位保持查 M15，其他套层与剪叉线索查 W13–W15 | 分清嵌套环、套筒和剪叉动作；确认行程、是否允许翻转、是否需要展开保持、夹点、脱落及实际运动件数。M14／M15 的物理证据为制作自述，M15 另完成默认几何复现；不据此承诺改作后保持力或寿命，待查项不冒充现成成熟核心 |
| 可展开花形、菌盖或可转化为镂空曲面的轮廓 | 平展／穹顶两状态形变；可查 M11 | 是否接受 TPU、薄连接段与空隙、形态保持要求；不是两态按压锁止 |

在当前用途方案中默认只推荐 2–3 个最贴合主体且有实质差异的玩法；说明保留哪些外观特征、手如何操作、纯打印还是需要现成配件、预计件数及待验证项。相关证据卡见 [机构索引](mechanism-library.md) 与 [文创玩具机构](toy-mechanisms.md)，需标准机械零件时按[资料索引 R17](resource-library.md#r17-stemfie可打印机械零件源库)查 STEMFIE；只有[待查来源](mechanism-candidates.md)时明确标为“玩法可探索、机构依据未齐”，不列为已验证方案。不能为展示玩法提前建模、做运动动画或生成后续多视图。

需要组合体验时，按 [解压组合玩法](fidget-edc.md#组合玩法与实现代价) 区分单个机构的多种反馈、独立动作和相互驱动的动作；只推荐能服务当前主体及用途的组合，并说明新增零件和验证范围。已有合适单机构时不强行拼装。

把建议放进原有互动提问和方案验收，不追加一轮重复调查。选项按当前目标提供“采用【具体玩法】”“保持固定／保留现方案”“比较其他玩法”“给我提供更多选项”，允许文字补充；用户已要求可动或已排除某玩法时沿用，不重复提供已否决方向。选择玩法后才在后续参数任务核对具体行程、材料与接口，不能把动作意向等同于接受机构或打印授权。外观修改不涉及互动选择时不反复推销机构。

### 需要补充的偏好

每轮只询问尚未知的 1–3 项，依实际目标选取：

- 功能活动：部位、动作方向和范围、单手／双手、承重、限位、定位或回位。

- 解压体验：动作偏好、安静／有声反馈、阻力与段落感、桌面／口袋／钥匙扣及外购件接受度。产品方向见 [品类库](product-library.md)，机构细则见 [EDC 结构参考](fidget-edc.md)。

- 灯光文创：L 类先沿用或选择现成灯具／完整灯光组件，确认用户希望的发光位置与使用方式；尺寸阶段再查具体型号。仅做外壳、灯罩或安装座不自动引入自制电路与 CyberBrick。

- 电动、遥控或可编程：在用户选择后再讨论驱动、供电、体积、预算与控制；按 [参考索引](resource-library.md) 进入 CyberBrick 等可选扩展。手动关节不触发电子组件安装。

机械或可动结构先按 [成熟机构复用](mechanism-reuse.md) 从 [机构卡片](mechanism-library.md) 筛选相关候选，展示实物证据、核心保留范围及本次需验证内容；库内不适配时再定向查找或提出标准成品、自行设计备选，不为套模板改变已确认用途。按 [最少零件原则](design-rules.md) 优先选满足要求且实际零件总数最少的方案，在当前概念比较中说明件数与功能取舍，不额外增加确认阶段。按需查机构示意、真实配件或模板，说明当前候选的外观、稳定性、打印、装配及耐久取舍；没有收益时不强加机构。选择活动意向只解锁当前用途讨论，不等于接受具体结构或允许三维生成。确定用途方案后才进入参数和图纸任务；参数化执行见 [接入规则](parametric-structures.md)。

## 绘图中的共同判断

每轮展示实际图像后，先对照设计共识指出已实现的目标及一两个值得讨论的设计点，再给可执行的调整方向。例如开口可保留现状、融入背部曲线，或缩小但接受容量减少。避免只问“满意吗”或“要不要更好看”。

一轮优先调整一两个主要变量，如比例、姿态、功能融合、细节密度或配色，明确保留其他哪些部分。用户可用日常语言描述、标注位置、选择同视角局部对比或先听解释；不要要求用户掌握建模术语。生成替代图前确认本轮要探索的方向，选择“查看比较”只授权当前任务内的对比，不解锁下一阶段。

主视图接受前允许发散，接受后其他视图服务于同一设计的补全和一致性验证。背面、底部或内部未决结构可提供选项；若影响已接受的轮廓或功能，先修订并重新验收主视图及受影响设计，再继续。不把其他视图当成重新设计机会。

按 [多视图设计](multiview-design.md) 分别验收主视图、整套多视图和参数图。用户已满意且关键取舍解决后收敛，不为增加互动无限提出新方向。项目记录只保存共识、候选编号、排除理由及验收状态，不保存逐字对话。
